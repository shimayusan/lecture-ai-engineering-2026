# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：講座のことは知らないまま、一般的な学習講座の例として「レベル1（基礎・マスト課題）」「レベル2（応用・チャレンジ課題）」「レベル3（発展・ハイクラス課題）」という難易度別の構成を答えた。最後に「宿題の問題文を教えてくれればより正確に答えられる」と付け加えていた。
- 用語集の正しい意味と比べて気づいたこと：実際の3レベルは「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」で、どれか1つに取り組めば宿題は完了（原則として採点はしない）。モデルの回答は「基礎」「発展」という言葉は合っていたが、2つ目を「応用」とし、難易度別の課題として説明していた。「どれか1つで完了」という点には触れておらず、講座の定義とは違っていた。
- 表示できたトークン数（入力 / 出力）：いずれも `gemini-3.5-flash-lite`。「LoRAとは何ですか？」は 7 / 602（2.85秒）、講座固有の質問は 21 / 357（1.97秒）。LoRA は見出し付きの詳しい解説になり、講座固有の質問より出力が長かった。

## 宿題

- 取り組んだレベル：基礎・実装・発展
- 使ったモデル：基礎・実装は `gemini-3.5-flash-lite`（講座の既定値）。発展は `gemini-3.5-flash-lite` と `gemini-3.5-flash` を比較した
- やったこと：
  - **基礎**：「LoRAを一文で説明してください。」を temperature 0.0 / 0.7 / 1.5 で実行（`app/ask.py` に `--temperature` を追加）
  - **実装**：`app/ask.py` に `SessionManager` と `--session` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした
  - **発展**：応答時間と入出力トークン数を表示するようにし、同じ質問を複数のモデルで比較した
- 実験スクリプト：`uv run python -m lectures.01.try`（基礎→実装→発展を順に実行。発展ではAPI呼び出しの前に5秒待つ）

### 結果：基礎（temperature の違い）

| temperature | 応答時間 | 入力 / 出力トークン |
|---|---|---|
| 0.0 | 1.35秒 | 9 / 43 |
| 0.7 | 1.36秒 | 9 / 48 |
| 1.5 | 1.14秒 | 9 / 47 |

- 3つともLoRAの説明として正しい内容で、表現と出力トークン数が少し違った。
- 別の回に同じ実行をすると出力は 51 / 51 / 49 で、temperature 0.0 でも実行ごとに出力が変わった。

### 結果：実装（会話履歴）

- `uv run python -m app.ask --session` で「私の名前はしまゆうです。覚えて下さい。」→「私の名前は？」と続けて質問すると、「あなたの名前は、しまゆうさんです！」と答えた。
- 入力トークン数は 11 → 49 と増え、2回目には1回目のやり取りも一緒に送られていることが分かった。
- `try.py` でも「ハナ」で同じことを確認した（入力 13 → 53）。セッション終了時に履歴は破棄される。

### 結果：発展（モデル比較）

temperature 0.2、各1回。`--compare-model gemini-3.5-flash-lite --compare-model gemini-3.5-flash` で実行した回：

| 質問 | flash-lite 応答時間 | flash-lite 入力/出力 | flash 応答時間 | flash 入力/出力 |
|---|---|---|---|---|
| LoRAを一文で | 0.91秒 | 9 / 50 | 5.68秒 | 9 / 51 |
| RAGを一文で | 0.73秒 | 9 / 41 | 5.02秒 | 9 / 38 |

- `gemini-3.5-flash` は `flash-lite` より5〜6倍遅かった。短い説明では出力トークン数はほぼ同じ。

### うまくいかなかったこと

| モデル | 結果 |
|---|---|
| `gemini-3.8-flash` | 503（混み合い）。2回とも失敗 |
| `gemini-3.5-flash` | 503 が2回。最後の実行では 429（レート制限） |
| `gemini-2.5-flash` | 404「新規ユーザーには提供していない」 |

- 1回エラーが出るとスクリプト全体が止まる作りなので、オプションなしの実行は最後まで通せなかった。

### 気づき・考察（無料枠のレート制限との関係）

- 503 はサーバー側の混雑で、送る間隔を5秒あけても防げなかった。429 は送りすぎたときに出るレート制限で、同じ日に何度も実行した後に出た。どちらの上限（1分あたりか1日あたりか）に当たったかは確かめていない。
- 比較するモデルや質問を増やすほど呼び出し回数が増え、無料枠の上限やエラーに当たりやすくなる。モデル数×質問数を絞り、間隔をあけて送る必要がある。
- 応答時間は混み具合で変わりうる。各1回の結果なので、モデルの優劣はこれだけでは判断できない。
